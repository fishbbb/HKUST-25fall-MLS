# 第 6 课：测评，以及你根据数字做的判断

## 这一课在整门课的位置

第 5 课的训练准确率只说明权重适应了训练图。这一课建立一套不改权重的测量方法，并把 50000 张训练图切成训练集和验证集。你之后每一次优化，都用这一课的函数在验证集上比较。官方测试集在所有决定做完之后才测一次。

## 学完你要能说出的话

- 测评时调用 `model.eval()`，并用 `torch.no_grad()` 包住前向。前者改变 BatchNorm 和 Dropout 的行为，后者不建计算图。
- 从训练图里留出验证集。验证集不参与 `backward`，用来决定早停、学习率和一次改动留不留。
- 训练准确率高、验证准确率明显低，这是过拟合。两个都低，而且训练损失已经不再下降，这是还没把训练图学好。
- 保存的是 `state_dict`。加载时先建一个同样的 `CifarCNN`，再把参数填回去。
- 测试集准确率只报一次，报的是验证集上最好的那份权重。

## 为什么测评和训练的前向不一样

这个模型里有 BatchNorm 和 Dropout。

训练状态下，BatchNorm 用当前这个批次的均值和方差，并且更新内部记住的滑动平均。Dropout 随机把一些激活变成 0。这是你希望发生在 `train_one_epoch` 里的事。

测评时，批次可以很小，最后一个批次也许只有十几张。用这么小的批次去估计均值，数字会很跳。评估要用训练过程中积累下来的滑动平均。Dropout 若在测评时仍然随机丢弃，同一张图连测两次会得到不同分数，准确率就掺进了无关的随机性。`model.eval()` 同时把这两件事切换过去：BatchNorm 用滑动平均，Dropout 变成恒等映射。

`torch.no_grad()` 管的是另一件事。测评不调用 `backward`，计算图没有用处。关掉它，前向不会记录中间激活，内存占用小很多。漏掉 `no_grad` 通常仍能算出正确的准确率，只是费内存。漏掉 `eval` 则会算出一个和部署时不同的准确率。两句都写上。

## 从训练图里切出验证集

切的是样本编号，不是切文件。50000 张里留 5000 张做验证，45000 张做训练。种子固定为 42，以后每次运行都是这 5000 张，实验之间才能比较。

官方测试集单独建，用和验证集相同的预处理。注意：训练集可以有随机增强，验证集和测试集不可以。这一课大家都只用 `ToTensor()`，三边一致。第 7 课给训练集加随机裁剪和翻转时，验证集和测试集仍然只用 `ToTensor()`。

`random_split` 用起来短，但它切完之后两边共享同一个 `transform`。一旦训练变换和验证变换不同，这个办法会让验证图也被随机裁剪。下面用编号切分，再分别套变换，变换可以不同。

```python
import torch
from torch.utils.data import DataLoader, Subset
from torchvision import datasets, transforms


class WithTransform(torch.utils.data.Dataset):
    """在已经切好的子集外面套一层预处理。"""

    def __init__(self, subset, transform):
        self.subset = subset
        self.transform = transform

    def __len__(self):
        return len(self.subset)

    def __getitem__(self, index):
        # subset 里取出的是 PIL 图和 Python int，因为构造 CIFAR10 时没有传 transform。
        image, label = self.subset[index]
        image = self.transform(image)
        return image, label


def make_loaders(batch_size=64, val_size=5000, seed=42):
    # 这里不传 transform，保证切分之后训练和验证可以用不同的预处理。
    full_train = datasets.CIFAR10(root="data", train=True, download=True, transform=None)
    test_base = datasets.CIFAR10(root="data", train=False, download=True, transform=None)

    eval_transform = transforms.ToTensor()
    train_transform = transforms.ToTensor()

    generator = torch.Generator().manual_seed(seed)
    permutation = torch.randperm(len(full_train), generator=generator).tolist()
    val_indices = permutation[:val_size]
    train_indices = permutation[val_size:]

    train_ds = WithTransform(Subset(full_train, train_indices), train_transform)
    val_ds = WithTransform(Subset(full_train, val_indices), eval_transform)
    test_ds = WithTransform(test_base, eval_transform)

    train_loader = DataLoader(train_ds, batch_size=batch_size, shuffle=True, num_workers=0)
    # 验证和测试不打乱。打乱不改变准确率，但不打乱让你调试时能复现某一个批次。
    val_loader = DataLoader(val_ds, batch_size=batch_size, shuffle=False, num_workers=0)
    test_loader = DataLoader(test_ds, batch_size=batch_size, shuffle=False, num_workers=0)
    return train_loader, val_loader, test_loader


train_loader, val_loader, test_loader = make_loaders()
print(len(train_loader.dataset), len(val_loader.dataset), len(test_loader.dataset))
# 45000, 5000, 10000
```

45000 除以 64 余 8，所以训练集每个 epoch 的最后一个批次只有 8 张图。验证集 5000 张，最后一个批次有 8 张（`5000 = 78 × 64 + 8`）。这就是测评时要按张数加权、而不能把每个批次的平均损失再简单平均的原因。

同一张图的编号只会出现在 `train_indices` 或 `val_indices` 其中一边。这是验证集有效的前提。预处理不同也不能破坏这条：第 7 课改变的是像素怎么抖动，不是哪张图被拿去更新权重。

## 测评函数

损失和准确率都按张数加权，不要先对每个批次取平均再对批次取平均。最后一个批次短，如果它和满批次权重相同，整体数字会被这个小批次拉动。

```python
def evaluate(model, loader, criterion, device):
    model.eval()
    total_loss = 0.0
    correct = 0
    total = 0

    with torch.no_grad():
        for images, labels in loader:
            images = images.to(device)
            labels = labels.to(device)

            logits = model(images)
            loss = criterion(logits, labels)

            batch_size = labels.size(0)
            total_loss += loss.item() * batch_size
            pred = logits.argmax(dim=1)
            correct += (pred == labels).sum().item()
            total += batch_size

    return total_loss / total, correct / total
```

函数内部调用了 `model.eval()`。训练循环的下一轮开头有 `model.train()`，会把状态切回去。如果你在测评之后立刻又做一次前向来调试，记得自己现在处于 `eval` 状态。

整体准确率是 10 类合在一起的。再算一个每一类的召回：这类图里，有多少比例被预测成了这类。CIFAR-10 每类数量接近，整体准确率已经比较公平；分类别的数用来发现「猫和狗老是互认」这种具体问题。

```python
CLASS_NAMES = [
    "airplane", "automobile", "bird", "cat", "deer",
    "dog", "frog", "horse", "ship", "truck",
]


def per_class_accuracy(model, loader, device, num_classes=10):
    model.eval()
    correct = torch.zeros(num_classes)
    count = torch.zeros(num_classes)

    with torch.no_grad():
        for images, labels in loader:
            images = images.to(device)
            labels = labels.to(device)
            pred = model(images).argmax(dim=1)

            for cls in range(num_classes):
                mask = labels == cls
                count[cls] += mask.sum().item()
                correct[cls] += (pred[mask] == labels[mask]).sum().item()

    for cls in range(num_classes):
        acc = (correct[cls] / count[cls]).item()
        print(f"{CLASS_NAMES[cls]:12s} {acc:.3f}  ({int(correct[cls])}/{int(count[cls])})")
```

某一类特别低时，先怀疑的是特征而不是损失写错了：猫和狗、飞机和船，在 32×32 的分辨率上本来就容易混。这会影响到第 7 课你对「还要不要继续加正则」的判断。如果整体都低，先解决整体；如果整体已经不错、只有两类在互换，数据增强里的水平翻转对这两类帮助有限，因为左右翻转不改变「猫脸和狗脸都很像」这件事。

## 两个准确率怎么读

每个 epoch 结束都测一次验证集。训练集的准确率直接用 `train_one_epoch` 的返回值即可。那个返回值是在 Dropout 打开、BatchNorm 用当前批次的状态下算的，会比「把训练集再按 eval 模式测一次」略低。用它看趋势足够了。要和验证集做严格对比时，再用 `evaluate(model, train_loader, ...)` 在 eval 模式下测一次训练集。注意这样做会多花一轮前向的时间。

读数的时候用下面这张判断表。数字是说明用的典型形态，不是你必须跑出的标准答案。

| 你看到的 | 判断 | 下一步先做什么 |
| --- | --- | --- |
| 训练损失还在明显下降，两个准确率都还低 | 还没训够 | 继续训，先不要改结构 |
| 训练损失已经平了，训练准确率和验证准确率都低，而且两者接近 | 欠拟合：模型或训练过程没有把训练图学进去 | 检查学习率；确认单批次实验其实能过拟合；再考虑更强的模型 |
| 训练准确率高，验证准确率低一截，差距还在变大 | 过拟合 | 进入第 7 课：数据增强、确认 Dropout、降低学习率、早停 |
| 验证准确率跟着训练准确率一起上升到一个平台 | 这是当前这套设定的正常终点 | 保存这份权重，再决定要不要换模型 |

「低一截」在这个 10 类任务上，可以先把 10 个百分点以上的差距当作值得行动的信号。差 2 个百分点往往只是随机性。不要为了 0.3 个百分点去改一堆东西，你分不清是改动生效了还是验证集上的噪声。

还没训够和欠拟合要分开。只训了 1 个 epoch 就看到 40% 的准确率，这是正常的中途状态，不是模型不行。至少要看到训练损失进入平台，再宣布它学不动。

## 保存和加载

只保存参数字典。文件里没有类的源代码，所以加载时你得自己把 `CifarCNN()` 建出来。结构一旦对不上，`load_state_dict` 会报错，这是好事，它防止你把 10 类的权重填进一个 100 类的模型。

```python
# 保存。map 的键是第 4 课打出来的那些参数名。
torch.save(model.state_dict(), "cifar_cnn.pt")

# 加载。weights_only=True 表示只把文件内容当作张量来读。
loaded = CifarCNN().to(device)
state = torch.load("cifar_cnn.pt", map_location=device, weights_only=True)
loaded.load_state_dict(state)
loaded.eval()
```

`map_location=device` 的用处是：权重可能是在 GPU 上保存的，而这台机器只有 CPU。它会在读入时把张量放到 `device`。先 `load_state_dict` 再 `to(device)` 也可以，两种顺序选一种并保持习惯。

可以看一眼字典里有什么：

```python
print(list(state.keys())[:3])
print(state["classifier.4.weight"].shape)  # (10, 256)
```

整个 `model` 对象也能 `torch.save`，那种文件把类的引用一起写进去，换一台机器或改了类的位置就可能加载失败。这个项目统一保存 `state_dict`。

## 测试集只在最后打开一次

训练循环里不要调用 `test_loader`。你在验证集上选出最好的 epoch、最好的学习率、最好的一版数据增强之后，加载那一份 `state_dict`，再测测试集。

```python
state = torch.load("best_cifar_cnn.pt", map_location=device, weights_only=True)
model.load_state_dict(state)
test_loss, test_acc = evaluate(model, test_loader, criterion, device)
print(f"test loss {test_loss:.4f}  test acc {test_acc:.4f}")
```

如果测试准确率和验证准确率差得很多，优先怀疑验证集太小或者你用验证集做了太多次挑选，而不是再去测试集上调一轮学习率。测试集上再调，这个数字就失效了。

验证集 5000 张、每类大约 500 张。一个改动如果只让验证准确率变化 0.002，在这个规模上很不稳。第 7 课保留改动的标准会写成：验证准确率有清楚的提升，并且训练和验证的差距没有变得更糟。

## 把训练和测评接在同一个循环里

下面是一个短循环，跑 3 个 epoch，每个 epoch 都打印训练和验证。它用来确认两条管道都通。3 个 epoch 不是最终成绩。`best_cifar_cnn.pt` 会留下这 3 轮里验证准确率最高的权重。

```python
def train_one_epoch(model, loader, criterion, optimizer, device):
    model.train()
    total_loss = 0.0
    correct = 0
    total = 0
    for images, labels in loader:
        images = images.to(device)
        labels = labels.to(device)
        optimizer.zero_grad()
        logits = model(images)
        loss = criterion(logits, labels)
        loss.backward()
        optimizer.step()
        batch_size = labels.size(0)
        total_loss += loss.item() * batch_size
        correct += (logits.argmax(dim=1) == labels).sum().item()
        total += batch_size
    return total_loss / total, correct / total


device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
torch.manual_seed(42)

model = CifarCNN().to(device)
criterion = nn.CrossEntropyLoss()
optimizer = torch.optim.Adam(model.parameters(), lr=1e-3)

best_acc = -1.0
for epoch in range(1, 4):
    train_loss, train_acc = train_one_epoch(
        model, train_loader, criterion, optimizer, device
    )
    val_loss, val_acc = evaluate(model, val_loader, criterion, device)
    print(
        f"epoch {epoch}  "
        f"train {train_acc:.3f}  val {val_acc:.3f}"
    )

    if val_acc > best_acc:
        best_acc = val_acc
        torch.save(model.state_dict(), "best_cifar_cnn.pt")
```

比较时用的是 `val_acc > best_acc`。验证准确率持平不算变好，不覆盖已经保存的文件。

## 课后练习

**口述 1.** `model.eval()` 和 `torch.no_grad()` 各管什么？只说 BatchNorm、Dropout、计算图这三样。

**口述 2.** 训练准确率 0.93，验证准确率 0.71。你的判断是什么？下一步应该去改权重所看到的数据，还是先去看测试集？

**代码.** 写一个断言：加载 `best_cifar_cnn.pt` 之后，用同一个验证批次跑两次 `argmax`，两次预测应当完全相同。这个断言用来确认测评没有随机性。

**思考.** 你把验证集拿去更新了 1 个 epoch 的权重，然后继续用它选模型。这样选出的模型会有什么偏差？

## 参考答案

**口述 1.** `eval()` 让 BatchNorm 改用滑动平均，让 Dropout 停止随机丢弃。`no_grad()` 让这次前向不记录计算图。前者影响输出的数值，后者影响要不要为反向传播保存中间结果。

**口述 2.** 这是过拟合。下一步去改训练过程或训练数据，例如数据增强和早停，并用验证集重新测量。测试集先不要看，否则你后面会忍不住按测试集的好恶挑选改动。

**代码.**

```python
model.load_state_dict(torch.load("best_cifar_cnn.pt", map_location=device, weights_only=True))
model.eval()
images, _ = next(iter(val_loader))
images = images.to(device)
with torch.no_grad():
    first = model(images).argmax(dim=1)
    second = model(images).argmax(dim=1)
assert torch.equal(first, second)
```

如果断言失败，模型多半还在 `train()`，Dropout 两次丢弃了不同的单元。

**思考.** 验证集参与了权重更新之后，它就含有「被拟合过」的成分。用它选出来的学习率和轮数，会偏向这 5000 张图，验证准确率偏高。你失去了唯一一块用来做决定的、又没被梯度看过的数据。测试集若再被拿来补这个洞，测试成绩也不再干净。
