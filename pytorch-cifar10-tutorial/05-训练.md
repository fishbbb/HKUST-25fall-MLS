# 第 5 课：损失、优化器和训练循环

## 这一课在整门课的位置

模型和数据都有了。这一课把它们接起来，让权重真的发生变化。学完你要能把一个 batch 里的四步按顺序讲出来，并说明损失变小代表什么。这一课用很少的步数确认「循环是通的」。要不要训很久、怎么看有没有过拟合，是第 6、7 课的事。

## 学完你要能说出的话

- `CrossEntropyLoss` 接收 logits 和类别编号。正确类的分数越高于其他类，损失越小。
- Adam 拿着每个权重的梯度去改这个权重。学习率是步子的基本尺度。
- 每个 batch 四步：`zero_grad`、前向、`backward`、`step`。
- 梯度会在 `.grad` 里累加。不清空的话，这一批的梯度会叠在上一批上面。
- 先用一个小批次把损失训到明显下降，证明模型、损失、反向传播三件事是接通的。然后再上完整数据。

## 损失在比较什么

`CrossEntropyLoss` 做两件事：对 logits 做 log_softmax，再取正确类别那个位置的负对数。正确类的概率越接近 1，这个数越接近 0。正确类的概率越接近 0，损失越大。

用两行可以手算的 logits 看这个方向。同一组分数，标签如果就是最大分所在的类，损失较小；标签如果是最小分所在的类，损失较大。

```python
import torch
from torch import nn

criterion = nn.CrossEntropyLoss()

# 一行 logits。下标 0 的分数最高，下标 2 的分数最低。
logits = torch.tensor([[2.0, 0.5, -1.0]])

loss_when_correct = criterion(logits, torch.tensor([0]))
loss_when_wrong = criterion(logits, torch.tensor([2]))

print(loss_when_correct.item())  # 较小
print(loss_when_wrong.item())    # 较大
```

正式训练时，logits 的形状是 `(N, 10)`，标签的形状是 `(N,)`。损失默认对这 N 张图取平均，所以一个批次得到一个标量。`loss.backward()` 要求这个标量，它才能从这一个数出发往回传。

标签用类别编号，不要先做成 10 维的 0/1 向量。`CrossEntropyLoss` 要的目标就是一串 `int64`，形状 `(N,)`。

## 学习率在控制什么

梯度告诉你方向：把这个权重增大一点，损失会变大还是变小。学习率告诉你这一步走多远。Adam 在这个基本尺度上，还会按每个权重最近的梯度大小做调整。梯度一直很大的权重，步子会相对收敛；梯度很小的权重，步子不会小到完全不动。你要会讲的是这个行为，不必在面试里推导它的两个滑动平均。

这个例子的起点是 `lr=1e-3`。

- 学习率过大：损失不下降，或者上下乱跳，权重一步被推过了合适的区域。
- 学习率过小：损失在下降，但每个 epoch 只动一点点，你可能误以为模型能力不够。
- 合适的学习率：前几个 epoch 里，训练损失总体向下。

第 7 课会在验证准确率停滞时把学习率乘上 0.5。那是训练过程中的调整。这一课先用固定的 `1e-3` 把循环写对。

## 梯度为什么会累加

每个可学习参数旁边都有一块同形状的存储，叫 `.grad`。`backward()` 把这次算出的梯度加到这块存储里，而不是覆盖。这是库的设计：有些情况下你会故意多次 `backward()` 再统一更新。我们每个 batch 都想用「只属于这个 batch」的梯度，所以在前向之前把这块存储清成 0。

下面这个最小例子不涉及图像，只说明累加。

```python
import torch

weight = torch.tensor([1.0], requires_grad=True)

loss = (weight * 3).sum()
loss.backward()
print(weight.grad)  # tensor([3.])

# 再反传一次，不清空。新的梯度 3 加到原来的 3 上。
loss = (weight * 3).sum()
loss.backward()
print(weight.grad)  # tensor([6.])

weight.grad.zero_()
print(weight.grad)  # tensor([0.])
```

训练代码里用 `optimizer.zero_grad()` 做同一件事。优化器知道它名下所有参数，一次把这些 `.grad` 都清掉。清梯度要在这个 batch 的前向之前做，至少要在 `backward()` 之前做。

## 一个 batch 的四步

把模型、损失、优化器先建好。这里用随机数据，让你看清四步，不依赖下载数据集。

```python
import torch
from torch import nn

torch.manual_seed(42)

device = torch.device("cuda" if torch.cuda.is_available() else "cpu")

model = CifarCNN().to(device)
criterion = nn.CrossEntropyLoss()
optimizer = torch.optim.Adam(model.parameters(), lr=1e-3)

# 假的一个批次。标签是 0 到 9 的整数。
images = torch.rand(64, 3, 32, 32, device=device)
labels = torch.randint(0, 10, (64,), device=device)

model.train()                  # BatchNorm 用当前批的统计量，Dropout 开启
optimizer.zero_grad()          # 1. 清空上一批留下的梯度
logits = model(images)         # 2. 前向，logits 形状 (64, 10)
loss = criterion(logits, labels)
loss.backward()                # 3. 反向传播，每个参数的 .grad 被填上
optimizer.step()               # 4. Adam 按梯度更新参数
```

`model.to(device)` 把全部权重要么放进显存，要么留在内存。`images` 和 `labels` 必须已经在同一个 `device` 上。

`model.train()` 对这个网络是必须的，不只是仪式。漏掉它的时候，如果模型还停在 `eval()`，BatchNorm 不用当前批次的统计量，Dropout 也不丢弃，你看到的损失和真正训练时不是一回事。

更新之前可以看一眼最后一层有没有梯度。四步走完再看权重，应当和更新前不同。

```python
# 把上面的 step 先注释掉，才能在更新前观察梯度。
# 观察完再执行 optimizer.step()。
last_weight = model.classifier[4].weight
print(last_weight.grad.shape)          # 和权重一样，是 (10, 256)
print(last_weight.grad.abs().mean())   # 应当是一个正数，说明梯度传到了最后一层
```

如果这里打印出来梯度是 `None` 或全是 0，就不要去训完整数据。先查：损失是不是标量、`forward` 里是不是用了没有登记到 `self` 上的层、是不是在 `no_grad` 里做的前向。

## 先过拟合一个批次：检查管道是否接通

完整的 CIFAR-10 有 50000 张图。一上来训很多轮，损失不降时你分不清是学习率的问题、代码写错，还是任务本身就难。标准的检查是：只拿几十张图，反复训练几十步。模型和优化器如果是通的，这几十张图会被记住，损失会明显下降。

下面这段使用真实的 CIFAR-10 批次。数据部分和第 3 课相同。

```python
import torch
from torch import nn
from torch.utils.data import DataLoader
from torchvision import datasets, transforms

torch.manual_seed(42)
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")

train_ds = datasets.CIFAR10(
    root="data",
    train=True,
    download=True,
    transform=transforms.ToTensor(),
)
train_loader = DataLoader(train_ds, batch_size=64, shuffle=True, num_workers=0)

# 只取一个批次，固定住。后面 40 步都在看这 64 张图。
fixed_images, fixed_labels = next(iter(train_loader))
fixed_images = fixed_images.to(device)
fixed_labels = fixed_labels.to(device)

model = CifarCNN().to(device)
criterion = nn.CrossEntropyLoss()
optimizer = torch.optim.Adam(model.parameters(), lr=1e-3)

model.train()
for step in range(40):
    optimizer.zero_grad()
    logits = model(fixed_images)
    loss = criterion(logits, fixed_labels)
    loss.backward()
    optimizer.step()

    if step % 10 == 0 or step == 39:
        pred = logits.argmax(dim=1)
        acc = (pred == fixed_labels).float().mean().item()
        print(f"step {step:02d}  loss {loss.item():.4f}  acc {acc:.2f}")
```

你应当看到损失总体下降，第 39 步的准确率明显高于第一步。第一步的准确率多半在 0.1 附近。如果 40 步之后损失几乎是一条横线，把学习率换成 `1e-2` 再试一次这个小实验。如果换成更大学习率仍然完全不动，回到模型和 `zero_grad` 的代码上去查，不要进入完整训练。

这个小实验会把这 64 张图的样子写进权重。它只用来排查。排查结束，丢掉这个 `model` 和 `optimizer`，重新 `CifarCNN()` 一个新的，再开始正式训练。

## 正式的一个 epoch

正式训练时，每个批次的图都不同。一个 epoch 结束，训练集里的每张图都参与了一次更新。下面的函数返回这一轮的平均损失和准确率，方便你看「训练本身在不在进步」。这两个数不能代替验证集，第 6 课会单独算验证。

```python
def train_one_epoch(model, loader, criterion, optimizer, device):
    model.train()
    total_loss = 0.0
    correct = 0
    total = 0

    for images, labels in loader:
        images = images.to(device)
        labels = labels.to(device)

        optimizer.zero_grad()
        logits = model(images)
        loss = criterion(logits, labels)
        loss.backward()
        optimizer.step()

        # loss.item() 是这个批次的平均损失。
        # 乘上本批次的张数，稍后除以总张数，最后一个小批次才不会被当成和 64 张一样重。
        batch_size = labels.size(0)
        total_loss += loss.item() * batch_size
        pred = logits.argmax(dim=1)
        correct += (pred == labels).sum().item()
        total += batch_size

    return total_loss / total, correct / total
```

跑一个 epoch，确认损失能打印出来、程序能走完。CPU 上一个 epoch 可能要几分钟到更久，视机器而定。

```python
model = CifarCNN().to(device)
criterion = nn.CrossEntropyLoss()
optimizer = torch.optim.Adam(model.parameters(), lr=1e-3)

train_loss, train_acc = train_one_epoch(
    model, train_loader, criterion, optimizer, device
)
print(f"epoch 1  loss {train_loss:.4f}  acc {train_acc:.4f}")
```

一个 epoch 之后，训练准确率通常会离开 10% 一点，但还远不到能汇报的程度。CIFAR-10 比「看清一个手写数字」难。这个网络一般要几十个 epoch 才进入能讨论的区间。第 7 课给它最多 40 个 epoch，并且允许提前停。不要根据某一个魔法轮数来宣布训练完成。

多轮的骨架就是把上面的函数放进循环。这里先写出 3 轮，让你看到损失逐轮变化。这 3 轮是观察用的，不是最终模型。

```python
for epoch in range(1, 4):
    train_loss, train_acc = train_one_epoch(
        model, train_loader, criterion, optimizer, device
    )
    print(f"epoch {epoch}  loss {train_loss:.4f}  acc {train_acc:.4f}")
```

注意第 2 轮不要重新 `CifarCNN()`，也不要重新建优化器。重新建模型会把权重打回随机；重新建 Adam 会丢掉它为每个参数记住的状态。一个训练过程共用同一个 `model` 和同一个 `optimizer`。

## 你在这一课要形成的判断

看训练损失的前几轮，只判断三件事里的一件：

- 损失总体下降：管道是通的，可以进入测评，看它在新图上怎么样。
- 损失是 NaN，或者一下子变成几万：学习率太大，或者输入里出现了不该出现的数值。先把学习率降到 `1e-4` 做一次单批次实验。
- 损失完全是平的：梯度没有传到权重，或者学习率小到可以当成 0。用上面「看最后一层 `grad`」的办法定位。

这个判断先不要用测试集。训练损失只回答「权重有没有在被这批训练图推动」。

**口述 2.** 为什么 `zero_grad` 不能省？用「梯度存在哪里、第二次会怎样」来讲。

**代码.** 用一个 `(4, 10)` 的 logits 和一个长度为 4 的标签，算出一个标量损失并打印。再写出从 logits 得到预测类别的那一行。

**思考.** 单批次实验里，40 步之后这 64 张图的准确率到了 100%，但你还没有看过另外 49936 张训练图。这时你能下的结论是什么，不能下的结论是什么？

## 参考答案

**口述 1.** `optimizer.zero_grad()` 把参数上一次的梯度清零。`model(images)` 用当前权重算出 logits，不改权重。`loss.backward()` 把梯度填进每个参数的 `.grad`，仍然不改权重本身。`optimizer.step()` 才按梯度和学习率改写权重。

**口述 2.** 梯度存在参数的 `.grad` 里，`backward()` 是往里面加。不清空的话，这一批算出的梯度会加上上一批的梯度，更新方向不再是这一批数据该有的方向。

**代码.**

```python
import torch
from torch import nn

criterion = nn.CrossEntropyLoss()
logits = torch.randn(4, 10)
labels = torch.tensor([1, 0, 7, 3])
loss = criterion(logits, labels)
print(loss.item())
pred = logits.argmax(dim=1)
```

**思考.** 能下的结论：模型容量、损失函数、反向传播和优化器是接通的，这 64 张图的标签已经被当前权重记住。不能下的结论：模型已经学会了 CIFAR-10，也不能说它在新图上有同样的准确率。单批次能记住，只是排查管道的手段。
