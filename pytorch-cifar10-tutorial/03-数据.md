# 第 3 课：把 CIFAR-10 读成批次

## 这一课在整门课的位置

第 2 课的图像和标签是你手工造的。这一课换成真实的 CIFAR-10，并且让它按批流出来。读完之后，你手里会有一个训练集的 `DataLoader`。测试集这一课只确认它存在，先不拿来做任何结论。验证集的切分放到第 6 课，因为那一课才用它做决定。

## 学完你要能说出的话

- `Dataset` 负责「问它第 i 号样本」，返回一张图和一个标签。
- `DataLoader` 负责把多个样本拼成批次，训练时打乱顺序，并在最后一个批次不足时照实给一个小批次。
- `transforms.ToTensor()` 把像素从 0–255 的整数变成 0–1 的浮点，同时把形状从高宽通道换成通道高宽。
- 训练集是用来改权重的。一张图参与过权重更新，就不能再拿它的准确率当作模型面对新图的成绩。

## 两个对象各管什么

`torchvision.datasets.CIFAR10` 是一个 `Dataset`。它知道数据在磁盘的哪个文件夹，知道一共有多少张，也知道第 i 张图的标签。你对它使用 `len(dataset)` 和 `dataset[i]`。

`DataLoader` 不存另一份图片。它只是一个取数的策略：每次从 `Dataset` 里抽 `batch_size` 张，把它们在新的第 0 维上叠起来，变成第 2 课说的 `(N, 3, 32, 32)` 和 `(N,)`。`shuffle=True` 时，每个 epoch 开始都会重新排列取数顺序。

把两者分开是有原因的。预处理和索引属于数据本身。批次大小、是否打乱，属于你这一次训练的策略。换一个批次大小，不需要重新下载数据。

## 预处理：`ToTensor`

CIFAR-10 在磁盘上是 PIL 图片，像素是 0 到 255 的整数，形状可以理解成高、宽、通道。卷积和损失希望看到浮点张量，而且通道在前。`transforms.ToTensor()` 一次做完这两件事：除以 255，得到 `[0, 1]` 上的 `float32`，再把维度排成 `(3, 32, 32)`。

训练集和测试集都要做这一步。如果只把训练集缩放到 `[0, 1]`，测试集还是 0–255，模型等于在两种完全不同的数值范围上工作，准确率没有意义。

这一课先只做 `ToTensor()`。随机裁剪、水平翻转留到第 7 课。那些变换会故意改动图的内容，用来缓解过拟合，它们只加在训练集上。现在加进去，会让你看不清「读进来的原始图长什么样」。

## 读训练集，并看一个批次

下面这段代码会把 CIFAR-10 下载到 `./data`。第一次运行需要网络，压缩包大约一百多 MB。下载后再次运行不会重复下载。

```python
import torch
from torch.utils.data import DataLoader
from torchvision import datasets, transforms

# 像素 0–255 -> 0–1 的 float32，形状从 HWC 换成 CHW。
transform = transforms.ToTensor()

# train=True 读取官方的 50000 张训练图。
# 根目录 data 不存在时，datasets 会自己创建。
train_ds = datasets.CIFAR10(
    root="data",
    train=True,
    download=True,
    transform=transform,
)

# 官方测试集先建出来，确认数量是 10000。这一课不迭代它。
test_ds = datasets.CIFAR10(
    root="data",
    train=False,
    download=True,
    transform=transform,
)

print("train", len(train_ds), "test", len(test_ds))

# 第 0 号样本：一张图、一个 Python int 标签。
image0, label0 = train_ds[0]
print(image0.shape, image0.dtype, label0)

# batch_size=64：每个批次 64 张。
# shuffle=True：每个 epoch 重新打乱，模型看不到固定的先后顺序。
# num_workers=0：在主进程里读图。教程用 0 是为了少碰多进程的环境问题。
# 机器确认能跑之后，可以改成 2 或 4，让读图和计算重叠。
train_loader = DataLoader(
    train_ds,
    batch_size=64,
    shuffle=True,
    num_workers=0,
)

images, labels = next(iter(train_loader))
print(images.shape, images.dtype)   # (64, 3, 32, 32) float32
print(labels.shape, labels.dtype)   # (64,) int64
print(labels[:8])                   # 前 8 个类别编号
```

`next(iter(train_loader))` 只取第一个批次就停。正式训练时会写 `for images, labels in train_loader`，把所有批次走完。50000 除以 64 等于 781 余 16，所以一个 epoch 有 782 个批次，最后一个批次的 `images.shape[0]` 是 16，不是 64。写测评代码时要把这个小批次算进去，第 6 课的累加方式会处理它。

类别名字的顺序和编号是固定的，来自数据集本身，不是按字母排的。

```python
CLASS_NAMES = [
    "airplane", "automobile", "bird", "cat", "deer",
    "dog", "frog", "horse", "ship", "truck",
]

print(CLASS_NAMES[label0], CLASS_NAMES[labels[0].item()])
```

`labels[0]` 是零维张量，`.item()` 把它变成 Python `int`，才能用作列表下标。

## 为什么训练要打乱，又要分成批次

打乱针对的是顺序。如果不打乱，模型会反复按「先看到一大段某一类、再看到另一类」的方式更新。有些类别的梯度会在一个 epoch 里扎堆出现。每个 epoch 重新打乱，每个批次里的类别更混合，梯度的方向更像整个训练集的平均。

分成批次针对的是内存和梯度的质量。一次把 50000 张都送进去，激活值会占很多内存，小机器放不下。一次只送 1 张，梯度是这一张图的梯度，方向跳动很大，损失曲线会很碎。64 是一个起点：一个批次的梯度是 64 张图的平均，方向比单张稳，显存也放得下。

批次大小是你的选择，不是数据的属性。改成 32 或 128，模型结构不用动。变大时梯度更稳，学习率有时也要一起调；变小时噪声更大，正则效果会稍强一点，但这一课先不要靠它做优化。第 7 课的优化手段是数据增强、Dropout、学习率和早停。批次大小保持 64，方便你比较每次改动。

## 为什么不能用训练图宣布「学好了」

权重的每一次更新，都看过了这一批训练图的标签。模型有能力把这些具体的图和标签记下来，尤其当网络足够大、又训练了足够久。记下来之后，再拿同样的图去考它，准确率会很高，这个数字只证明「这些图它见过」。

你关心的是下一张没见过的图。所以测评用的图必须没有参与梯度更新。官方已经留了 10000 张测试图。更严格的做法是：连「我要不要换一个学习率」这种决定，也不要看这 10000 张。否则你是在用测试集挑选模型。第 6 课会从 50000 张里切出验证集来承担这个职责，测试集继续封存。

这一课只要把规则记牢：`train_loader` 里的图，将来只用来做 `loss.backward()` 和 `optimizer.step()`。

## 看一张图，确认预处理没有把内容毁了

训练之前值得看一眼。`ToTensor()` 之后像素在 `[0, 1]`，画图时 matplotlib 直接接受这个范围。通道要换回最后一维。

```python
import matplotlib.pyplot as plt

# 取批次里的第 0 张，放到 CPU，换成 HWC 的 numpy。
# 这一步只为了给人看，不参与训练。
show = images[0].detach().cpu().permute(1, 2, 0).numpy()
plt.imshow(show)
plt.title(CLASS_NAMES[labels[0].item()])
plt.axis("off")
plt.show()
```

图应当是一张能认出大致轮廓的彩色小图，而不是噪声，也不是全黑全白。如果全是噪声，多半是维度顺序错了，比如把通道和宽弄反了。

## 固定随机性，方便你以后比较

数据打乱、权重初始化都用到随机数。你之后要比较「加了数据增强」和「没加」两次实验。如果两次的验证集划分都不一样，准确率差异可能来自分组，而不是来自增强。从现在起，涉及随机的地方使用同一个种子。

```python
torch.manual_seed(42)
```

这行要写在创建 `DataLoader` 之前，它才会影响 `shuffle` 的第一次打乱。第 6 课切分验证集时会再用一次同一个种子，保证每个人、每次运行切出来的验证集是同一批图。

## 课后练习

**口述 1.** `Dataset` 和 `DataLoader` 各负责什么？这个项目里谁知道「第 100 张图是不是猫」？

**口述 2.** 解释 `ToTensor()` 对一个像素值 255 和一个像素值 0 分别做什么，形状从什么变成什么。

**代码.** 取一个批次，打印最后一张图对应的类别英文名，并打印这个批次里标签的最小值和最大值。最小值应当大于等于 0，最大值应当小于等于 9。

**思考.** 有人提议：为了让汇报数字更好看，训练完再把训练集和测试集合并，在全部 60000 张上算一个准确率。这个数字会有什么问题？

## 参考答案

**口述 1.** `Dataset` 按编号返回样本，CIFAR-10 的 `Dataset` 知道第 100 张图和它的标签。`DataLoader` 决定每次取多少张、取的顺序，并把它们叠成批次。

**口述 2.** 255 变成 `1.0`，0 变成 `0.0`，中间的值线性地除以 255。一张图从高 32、宽 32、通道 3，变成通道 3、高 32、宽 32 的 `float32` 张量。

**代码.**

```python
last_name = CLASS_NAMES[labels[-1].item()]
print(last_name, int(labels.min()), int(labels.max()))
```

**思考.** 合并之后，50000 张训练图上的成绩被混进了最终数字。模型在这些图上更新过权重，这块准确率偏高，会把 10000 张新图上的真实表现拉得好看。听众无法从这个合在一起的数里把两者拆开。汇报应当单独给出测试集准确率。
