# 第 8 课：同一任务上的微调

## 这一课在整门课的位置

第 7 课的手段都用在同一个小 CNN 上。那些手段解决过拟合和「哪一轮的权重该留下」。如果验证准确率已经和训练准确率一起进入平台，加再多的翻转也不会出现一个新的模型。这一课换起点：使用 ImageNet 上预训练的 MobileNetV2，在 CIFAR-10 上继续训练。任务没变，还是这 10 个类别。变的是权重从哪里开始，以及输入要配合这套权重做什么样的预处理。

## 学完你要能说出的话

- 从零训练时，权重是随机初始化的。微调时，大部分权重来自别人在 ImageNet 上训好的结果，已经能够响应边缘、颜色和简单的部件。
- 预训练网络的最后一层是 1000 类。我们换成 10 类，这一层是随机初始化的，必须训练。
- 第一段先冻结前面的特征层，只训练新的分类头。第二段再解冻，用更小的学习率更新整个网络。
- 预处理要和权重的来源一致。这套权重期望 224×224 的输入，并使用 ImageNet 的均值和方差。从零训练的小 CNN 仍然用 32×32 和 `ToTensor()`，两套预处理不要混用。
- 解冻之后要重新建立优化器。Adam 只为当初交给它的那些参数保存状态。

## 什么时候走这条路

微调不是因为 MobileNet 这个名字更高级，而是因为起点不同。ImageNet 有上百万张、一千个类别的图。那里学到的前几层，对「这是一张自然图像」这件事是有用的。CIFAR-10 也是自然图像，只是分辨率低、类别少。把这套特征拿过来，通常比随机权重更快进入一个不错的验证准确率，尤其是当你自己的标注没有 45000 张那么多的时候。

这个教程的训练集有 45000 张，从零训练一个小 CNN 是站得住的，第 4 到第 7 课不是白做的。你讲的时候把两条路分成两种条件：

- 我想先确认自己能把数据、损失、训练循环和测评写对，并且模型要小、输入保持 32×32。用 `CifarCNN`。
- 小 CNN 的验证准确率到了平台，或者我只有很少的标注，希望借用大数据集上的特征。用预训练的 MobileNetV2。

两条路共用第 6 课的验证集编号和「测试集最后测一次」的规则。

## 把分类头换成 10 类

`torchvision.models.mobilenet_v2` 可以带上 `MobileNet_V2_Weights.DEFAULT`。第一次运行会下载权重文件。网络的 `features` 是卷积特征，`classifier` 是一个 `Sequential`：先 Dropout，再一个全连接到 1000 类。`last_channel` 是 1280，也就是这个全连接层的输入特征数。

我们替换的是最后那个全连接，让它输出 10。前面的 Dropout 留着。

```python
import torch
from torch import nn
from torchvision.models import mobilenet_v2, MobileNet_V2_Weights

weights = MobileNet_V2_Weights.DEFAULT
model = mobilenet_v2(weights=weights)

# classifier[0] 是 Dropout，classifier[1] 是原来的 1000 类全连接。
# 新的全连接是随机初始化的，这是第一段必须训练的原因。
model.classifier[1] = nn.Linear(model.last_channel, 10)
```

替换之后，旧的 1000 类权重被丢掉。特征层的权重还在。打印最后一层的形状应当是输入 1280、输出 10：

```python
print(model.classifier[1].weight.shape)  # (10, 1280)
```

## 预处理必须换成这套权重认识的样子

`CifarCNN` 从 32×32 学起，`ToTensor()` 把像素放到 `[0, 1]` 就够了。MobileNetV2 的权重是在 224×224 上、并且按 ImageNet 的均值和方差标准化之后训出来的。直接把 32×32、`[0, 1]` 的张量送进去，卷积核看到的数值范围和空间尺度都和当初不同，预训练的优势会丢掉。

几何上，把 32×32 放大到 224×224。放大不会凭空增加细节，这是一个诚实的代价：计算量上去了，画面变模糊。换它的理由只是「和预训练时的输入规格对齐」。标准化使用下面这组固定的均值和方差，三个通道各一组。

```python
IMAGENET_MEAN = (0.485, 0.456, 0.406)
IMAGENET_STD = (0.229, 0.224, 0.225)

train_transform = transforms.Compose([
    transforms.Resize(224),
    transforms.RandomHorizontalFlip(),
    transforms.ToTensor(),
    transforms.Normalize(IMAGENET_MEAN, IMAGENET_STD),
])

eval_transform = transforms.Compose([
    transforms.Resize(224),
    transforms.ToTensor(),
    transforms.Normalize(IMAGENET_MEAN, IMAGENET_STD),
])
```

训练集保留水平翻转，原因和第 7 课相同。验证集和测试集只做缩放、转张量和标准化，保证测出来的数是固定的。`Resize` 放在 `ToTensor` 之前，作用在 PIL 图上。

第 6 课的 `make_loaders` 只要换成这两个 `transform`，切分编号和种子保持 42。不要把 `Normalize` 只加在训练边上。验证图如果还是 `[0, 1]`，而训练图已经被减过均值、除过方差，验证准确率会非常差，这个差不代表模型不行，只代表两边的数值尺度不同。

官方权重对象也带一份评估用的预处理 `weights.transforms()`，里面是先缩放到 256 再中心裁到 224，加上同一组均值方差。正方形的图用我们写的 `Resize(224)` 更直接，也方便在训练集上插入翻转。你要能说出均值和方差这组数来自 ImageNet 预训练，而不是 CIFAR-10 算出来的。

## 第一段：冻结特征，只训练分类头

新的分类头是随机的，一开始会输出接近瞎猜的 10 个分数。如果这时就用比较大的学习率更新整个网络，特征层会被这些随机分数产生的梯度带偏，预训练的特征还没被好好利用就损掉了。

第一段把 `features` 里所有参数的 `requires_grad` 设为 `False`。优化器只接收 `requires_grad` 仍为 `True` 的参数，也就是分类头。

冻结还有第二层含义。`features` 里有 BatchNorm。就算权重不更新，只要模型处于 `train()`，BatchNorm 仍会用当前批次更新它的滑动均值和方差。那些统计量是在 ImageNet 上积累的，不应当被 64 张 CIFAR 图迅速改写。所以第一段里，每个 batch 都把 `features` 设回 `eval()`，同时整个模型先 `train()`，让分类头里的 Dropout 仍然工作。

```python
def freeze_features(model):
    for param in model.features.parameters():
        param.requires_grad = False


def train_one_epoch_finetune(model, loader, criterion, optimizer, device, freeze_backbone):
    model.train()
    if freeze_backbone:
        # Dropout 所在的 classifier 保持训练状态。
        # 特征层的 BatchNorm 保持评估状态，不更新滑动统计量。
        model.features.eval()

    total_loss = 0.0
    correct = 0
    total = 0
    for images, labels in loader:
        images = images.to(device)
        labels = labels.to(device)

        optimizer.zero_grad()
        logits = model(images)
        loss = criterion(logits, labels)
        loss.backward()
        optimizer.step()

        batch_size = labels.size(0)
        total_loss += loss.item() * batch_size
        correct += (logits.argmax(dim=1) == labels).sum().item()
        total += batch_size

    return total_loss / total, correct / total
```

第一段的优化器和循环：

```python
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
model = model.to(device)
criterion = nn.CrossEntropyLoss()

freeze_features(model)
head_params = [p for p in model.parameters() if p.requires_grad]
optimizer = torch.optim.Adam(head_params, lr=1e-3)

# 分类头从随机权重开始，轮数不用很多。这里用 3 轮作为第一段的长度。
for epoch in range(1, 4):
    train_loss, train_acc = train_one_epoch_finetune(
        model, train_loader, criterion, optimizer, device, freeze_backbone=True
    )
    val_loss, val_acc = evaluate(model, val_loader, criterion, device)
    print(f"head epoch {epoch}  train {train_acc:.3f}  val {val_acc:.3f}")
```

`evaluate` 用第 6 课那个函数，不必重写。它会 `model.eval()`，整网都不更新统计量，适合测评。

这一段结束时，分类头已经能把 1280 维特征对到 10 个类上，特征层还是下载来的那一份。

## 第二段：解冻，换更小的学习率，重建优化器

第二段允许特征层适应 CIFAR-10 的画面。步子要比第一段小，用 `1e-4`。步子大了，前几层会被少量数据改掉，出现「忘了 ImageNet 上有用的特征」的情况，验证准确率先升后掉。

Adam 在第一段只见过分类头的参数，它内部为这些参数记着动量一类的状态，特征层它根本没有登记。把 `requires_grad` 打开却沿用旧优化器，特征层不会被更新。所以第二段新建一个 Adam，把 `model.parameters()` 全部交进去。

```python
for param in model.features.parameters():
    param.requires_grad = True

optimizer = torch.optim.Adam(model.parameters(), lr=1e-4)
scheduler = torch.optim.lr_scheduler.ReduceLROnPlateau(
    optimizer, mode="max", factor=0.5, patience=2
)

best_acc = -1.0
bad_epochs = 0
for epoch in range(1, 16):
    train_loss, train_acc = train_one_epoch_finetune(
        model, train_loader, criterion, optimizer, device, freeze_backbone=False
    )
    val_loss, val_acc = evaluate(model, val_loader, criterion, device)
    scheduler.step(val_acc)

    if val_acc > best_acc:
        best_acc = val_acc
        bad_epochs = 0
        torch.save(model.state_dict(), "best_mobilenet_cifar.pt")
    else:
        bad_epochs += 1
        if bad_epochs >= 6:
            print("微调阶段早停")
            break

    print(
        f"tune epoch {epoch:02d}  train {train_acc:.3f}  val {val_acc:.3f}  "
        f"lr {optimizer.param_groups[0]['lr']:.6f}"
    )
```

`freeze_backbone=False` 时，函数里不会把 `features` 设成 `eval()`。第二段的 BatchNorm 可以适应新的数据。这是两段之间一个实质差别，不只是学习率不同。

保存的文件名换成 `best_mobilenet_cifar.pt`，不要覆盖小 CNN 的 `best_cifar_cnn.pt`。两份权重属于两个结构，加载时也要建回对应的结构：一个是 `CifarCNN()`，一个是替换过分类头的 `mobilenet_v2`。把 MobileNet 的 `state_dict` 填进 `CifarCNN` 会直接对不上键。

第二段的轮数、耐心都比第 7 课短一档，因为起点已经不差，而且 224 的输入更贵。这是预算上的选择。判断标准没变：看验证准确率留最好的一份。

## 输入变大这件事要一起讲

32×32 变成 224×224，像素数大约是原来的 49 倍。批次大小 64 在小 CNN 上很轻松，在 MobileNetV2 上可能显存不够。显存不够时，把 `batch_size` 降到 32 或 16，其他代码不变。准确率仍然按张数加权，所以批次大小改变不会让公式失效。你比较小 CNN 和 MobileNet 时，要同时说出这条代价：验证准确率如果更高，付的是每次前向更贵、需要把图放大。

## 和从零训练对照着讲

| | 从零训练的 CifarCNN | 微调 MobileNetV2 |
| --- | --- | --- |
| 权重起点 | 随机 | 特征层来自 ImageNet，分类头随机 |
| 输入 | 32×32，像素缩放到 `[0, 1]` | 224×224，再按 ImageNet 均值和方差标准化 |
| 第一段更新谁 | 全部权重 | 只更新分类头，特征层的 BatchNorm 也不更新统计量 |
| 第二段 | 没有第二段，从头到尾都是全部权重 | 解冻全网，学习率用 `1e-4`，并新建优化器 |
| 怎么决定留哪一份 | 验证准确率最高的 `state_dict` | 同样的规则，文件分开保存 |
| 测试集 | 最后测一次 | 最后测一次，不参与上面的选择 |

测评函数、实验表、早停的含义都没有换。换的是模型和它要求的预处理。

**口述 2.** 为什么第二段不能继续用第一段那个 Adam 对象？

**代码.** 写一段检查：冻结之后，`features` 里所有参数的 `requires_grad` 都是 `False`，而 `classifier` 里至少有一个参数是 `True`。解冻之后，`features` 里的参数变回 `True`。

**思考.** 某人加载了 MobileNetV2 的预训练权重，但验证集忘了做 `Normalize`，训练集团做了。他看到训练损失在降、验证准确率一直在 10% 附近。请你判断：这更像模型容量不够，还是更像测评和训练的输入不一致？你要他先改哪一行？

## 参考答案

**口述 1.** 第一段学习率 `1e-3`，只更新新的 10 类分类头。特征层 `requires_grad` 是 `False`，并且处于 `eval()`，BatchNorm 继续使用 ImageNet 时期的滑动统计量。第二段学习率 `1e-4`，特征层和分类头都更新，特征层回到训练状态，BatchNorm 可以适应 CIFAR-10。

**口述 2.** Adam 在创建时登记参数，并为每个参数维护自己的状态。第一段创建时特征层没有被交进去。之后即使打开 `requires_grad`，这个旧优化器的 `step()` 也不会更新它们。第二段需要一个新的 Adam，参数列表是 `model.parameters()`。

**代码.**

```python
freeze_features(model)
assert all(not p.requires_grad for p in model.features.parameters())
assert any(p.requires_grad for p in model.classifier.parameters())

for param in model.features.parameters():
    param.requires_grad = True
assert all(p.requires_grad for p in model.features.parameters())
```

**思考.** 更像输入不一致。训练损失能降，说明分类头至少在「标准化之后的图」上学会了东西，容量不是第一嫌疑。验证图仍在 `[0, 1]`，和训练时的尺度不同，10% 就是十类上的随机水平。先改验证集的 `transform`，补上同一组 `Normalize`，再重新测。在这之前不要去加大学习率或加深层数。
