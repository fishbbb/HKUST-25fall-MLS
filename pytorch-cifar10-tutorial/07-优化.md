# 第 7 课：看到现象之后，怎么优化

## 这一课在整门课的位置

第 6 课给你判断表。这一课只处理表里「过拟合」和「验证准确率进入平台」这两行，因为这是这个小 CNN 在 CIFAR-10 上最常走到的地方。手段只有四种：训练集上的数据增强、已经放进模型的 Dropout、验证准确率停滞时降低学习率、连续停滞就早停并留下最好的权重。每用一种，都回到同一个验证集上重新测。

## 学完你要能说出的话

- 优化的顺序是：先说清现象，再说这个现象指向数据、模型还是训练过程，然后只改对应的那一处，最后用验证集决定留不留。
- 数据增强改的是训练图的外观，不改标签，也不改验证图。
- 学习率调度改的是更新的步长。早停改的是你采纳哪一个 epoch 的权重。
- 一次实验只加一组相关的改动，否则准确率变了你不知道是谁的功劳。

## 先写下一份实验记录

开口讲优化之前，先有一张表。没有表的时候，人会同时改五个东西，然后给一个故事。表强制你把故事写短。

| 实验 | 相对上一行改了什么 | 针对的现象 | 训练准确率 | 验证准确率 | 决定 |
| --- | --- | --- | --- | --- | --- |
| A 基线 | 只有 ToTensor，固定学习率 1e-3 | 建立参照 | 填你跑出来的数 | 填你跑出来的数 | 作为对照 |
| B | 训练集加随机裁剪和水平翻转 | 训练高、验证低 |  |  | 留或弃 |
| C | 在 B 上加学习率下降和早停 | 验证准确率进入平台 |  |  | 留或弃 |

教程不预填准确率。你自己跑出来的数字才是你能讲的数字。还没跑完时，口述就讲决策规则，不要编一个百分比。

保留一次改动的标准有两条，两条都要满足：

1. 验证准确率高于上一行，提升清楚，而不是 0.001 这种验证集噪声。
2. 训练准确率和验证准确率的差距没有明显变大。如果验证只高了一点点、差距却拉大了，这个改动是在更努力地记训练集，不留。

测试集不出现在这张表里。表上的决定全部做完，再用第 6 课的方式，加载留下的那份权重，对测试集测一次。

## 数据增强：改训练图，不改答案

过拟合的一种理解是：模型使用了只在这几张训练图上成立的线索，比如物体正好在画布中央、飞机头正好朝左。让训练图在送进网络之前做一些不改变类别的变化，这些过于具体的线索就不稳定了，权重会去抓更稳的线索。

这个数据集上选用两种：

- `RandomCrop(32, padding=4)`：先在四周补 4 个像素，再随机裁回 32×32。物体会在画面里平移一点。标签不变，因为平移不改变它是不是一架飞机。
- `RandomHorizontalFlip()`：以默认的 50% 概率左右翻转。这 10 个类别左右翻转之后仍然是原类别。

不用上下翻转。汽车、船、马有明确的上下方向，倒过来的图在测试集里几乎不出现。训练时大量加入这种图，等于在教模型一种考试里不会出现的变化。

验证集和测试集不做这两种随机变换。测评要的是一个固定的数。如果验证图每次都不一样，你无法判断是模型变好了还是这次裁剪比较幸运。

```python
train_transform = transforms.Compose([
    transforms.RandomCrop(size=32, padding=4),
    transforms.RandomHorizontalFlip(),
    transforms.ToTensor(),
])

# 验证和测试保持第 6 课的样子。
eval_transform = transforms.ToTensor()
```

`Compose` 按写下来的顺序执行。先在 PIL 图上裁剪和翻转，再 `ToTensor()`。顺序反了也能写，但裁剪的尺寸就要按张量的维度去改，更容易出错。这个教程统一先做几何变换，再转成张量。

把第 6 课 `make_loaders` 里的 `train_transform` 换成上面这一行，其余切分代码不变。验证集的 5000 个编号仍然不要进入训练集。

增强之后，单张训练图变难认一点，训练准确率常常会比基线低一些，这是预期的。你要看的是验证准确率升不升、两者的差距缩不缩。如果训练准确率掉了很多、验证准确率也掉了，增强过强，或者模型还没训够去适应这些变化。先把 epoch 预算给足，再决定减弱增强。

## Dropout 已经在模型里，确认它真的在工作

第 4 课的分类头有 `Dropout(0.5)` 和 `Dropout(0.3)`。它针对的是同一种现象：分类头不要依赖某几个特别大的激活才能把训练集分开。

你要确认的不是再把比例改来改去，而是它在正确的状态下。`train_one_epoch` 开头有 `model.train()`，Dropout 才会丢弃。`evaluate` 开头有 `model.eval()`，验证准确率才是「全部激活都在」的成绩。如果两边都是 `train()`，验证准确率会忽高忽低，实验表无法填写。

比例本身先不动。0.5 已经比较强。如果加上数据增强之后训练准确率长期上不去，同时验证也不高，那是正则过强，可以把 0.5 降到 0.3 做一次对照实验，并且在表里单独占一行。不要和数据增强的第一次引入写在同一行。

## 学习率下降：验证停滞时把步子变小

训练前期用 `1e-3`，损失下降得比较快。到了后期，权重已经在一个比较好的区域附近，同样的步子会跨过这个区域，验证准确率在一个平台上抖动，不再提高。这时把学习率乘以 0.5，让更新细一些。

`ReduceLROnPlateau` 盯着你交给它的那个数。我们盯验证准确率，所以 `mode="max"`，越大越好。连续 `patience` 个 epoch 没有超过历史最好，就把学习率乘上 `factor`。

```python
optimizer = torch.optim.Adam(model.parameters(), lr=1e-3)

scheduler = torch.optim.lr_scheduler.ReduceLROnPlateau(
    optimizer,
    mode="max",     # 监控准确率，越大越好
    factor=0.5,     # 触发时新学习率 = 旧学习率 × 0.5
    patience=3,     # 连续 3 个 epoch 没有刷新最好成绩才触发
)
```

每个 epoch 在算出 `val_acc` 之后调用一次：

```python
scheduler.step(val_acc)
print("lr", optimizer.param_groups[0]["lr"])
```

`param_groups[0]["lr"]` 是当前学习率。把它打在日志里。你讲实验的时候可以说「第几轮学习率从 0.001 变成了 0.0005，之后验证准确率又升了一点」或者「降了学习率也没有再升，于是早停」。没有这段日志，你只能说「我用了调度器」，说不出它有没有真的触发。

## 早停：停滞够久就停，并取验证集上最好的权重

学习率变小之后，再给模型一段观察期。如果验证准确率仍然不刷新最好成绩，继续训下去通常是在拉大过拟合的差距。早停就是停止循环，并且使用最好的那一份，而不是最后一轮的权重。最后一轮往往已经比最好的一轮更过拟合了。

早停的耐心要长过学习率的耐心。这里学习率的耐心是 3，早停的耐心是 8。这样至少能先等到一次学习率下降，并看到下降之后的几个 epoch，再决定放弃。如果两个耐心都是 3，学习率刚降下去你就停了，等于没给小步子机会。

```python
best_acc = -1.0
bad_epochs = 0
early_patience = 8
history = []

for epoch in range(1, 41):
    train_loss, train_acc = train_one_epoch(
        model, train_loader, criterion, optimizer, device
    )
    val_loss, val_acc = evaluate(model, val_loader, criterion, device)
    scheduler.step(val_acc)

    history.append({
        "epoch": epoch,
        "train_acc": train_acc,
        "val_acc": val_acc,
        "lr": optimizer.param_groups[0]["lr"],
    })

    if val_acc > best_acc:
        best_acc = val_acc
        bad_epochs = 0
        torch.save(model.state_dict(), "best_cifar_cnn.pt")
    else:
        bad_epochs += 1
        if bad_epochs >= early_patience:
            print(f"epoch {epoch}: 验证准确率连续 {early_patience} 轮没有提升，停止")
            break

    print(
        f"epoch {epoch:02d}  train {train_acc:.3f}  val {val_acc:.3f}  "
        f"best {best_acc:.3f}  lr {optimizer.param_groups[0]['lr']:.6f}"
    )
```

循环结束后，内存里的 `model` 是最后一轮的权重，不一定是最好的。汇报和测试之前要加载文件：

```python
best_state = torch.load("best_cifar_cnn.pt", map_location=device, weights_only=True)
model.load_state_dict(best_state)
val_loss, val_acc = evaluate(model, val_loader, criterion, device)
print("best checkpoint on val", val_acc)
```

`history` 是你填实验表和画曲线的材料。面试里如果被问「你怎么知道该停」，你就按 `history` 讲：训练准确率还在升、验证准确率已经连着若干轮不升，学习率降过一次仍然不升，于是停，并加载验证集上 `best_acc` 那一轮。

最多 40 个 epoch 是预算的上限，不是目标。早停触发就结束。如果 40 轮走完验证准确率还在稳稳上升，说明停早了，可以把上限加到 60 再跑一次，这在实验表里是新的一行，名字可以叫「加长预算」。

## 一次只改一组

推荐的实际顺序：

1. 先跑基线：`ToTensor()`、Adam `1e-3`、第 6 课的循环，给足 epoch，让它自己进入平台。把训练准确率、验证准确率写进表的 A 行。
2. 如果出现「训练明显高于验证」，只加入 `train_transform` 里的两种增强，其他不动，得到 B 行。
3. 如果 B 的验证准确率会上升到一个平台然后抖动，再在 B 的代码上加调度器和早停，得到 C 行。C 相对 A 改了不止一件事，所以表里写的是「相对上一行」。你比较的是 B 和 C，不是把三件事的功劳混在 A 和 C 的差别里。

欠拟合不要走这条路径。如果基线的训练准确率自己也上不去，先回到第 5 课的单批次实验，确认管道是通的；再把学习率试一次 `1e-2` 和一次 `1e-4`，各跑很短的几轮看训练损失的方向。这两次也各占实验表的一行。确认能学动之后，再讨论过拟合。

小 CNN 在这张实验表上走到头，验证准确率不再因为这些手段上升，就不要继续堆正则。正则解决的是「训练和验证有差距」。它不负责把一个容量不够的模型变成另一个模型。下一步是第 8 课：换一个已经在大数据集上训过的网络，作为新的起点。

## 你讲优化时的句式

用这个句式，避免把手段背成清单：

「我看到的现象是训练准确率升到了某一水平，验证准确率低一截，而且差距在变大。我判断这是过拟合，问题出在训练图的一些细节被记住了。我只改了训练数据的预处理，加上平移和水平翻转，验证集的预处理没动。重新测完，验证准确率从上一行的数变成了新的数，差距缩小，所以我留下这个改动。」

把「某一水平」换成你表里的数。没有数的时候，就停在判断和改动上，明确说成绩还在跑。

## 课后练习

**口述 1.** 用「现象、判断、改动、如何决定留不留」四段，讲一次数据增强。不要提测试集。

**口述 2.** 为什么早停的耐心比学习率调度的耐心长？停下来之后，你要使用哪一轮的权重？

**代码.** 写出 `train_transform` 和 `eval_transform`。再写一个小循环：从训练集里取同一张图两次，打印两次像素是否完全相同。你应当预期它们经常不相同。再从验证集取同一张图两次，它们应当相同。

**思考.** 实验 B 的验证准确率从 0.72 升到 0.74，训练准确率从 0.95 降到 0.88。实验 C 在 B 的基础上早停，验证准确率仍是 0.74，但你发现如果不早停、一直训到第 40 轮，验证准确率掉到 0.70，训练准确率升到 0.96。C 这个改动算不算留下？你汇报时用哪一个权重？

## 参考答案

**口述 1.** 现象是训练准确率明显高于验证准确率。判断是过拟合，模型在使用只属于这些训练图的线索。改动只发生在训练集的预处理：随机平移裁剪和水平翻转，标签不变，验证集仍然只做 `ToTensor()`。留下的条件是验证准确率有清楚提升，并且两个准确率的差距没有变大。

**口述 2.** 学习率先降，模型才有机会用更小的步子继续提高验证准确率。早停若和调度器一样短，降学习率这个动作就没有观察窗口。停下来之后使用验证准确率最高的那一轮，也就是 `best_cifar_cnn.pt` 里的权重，不是最后一轮。

**代码.**

```python
train_transform = transforms.Compose([
    transforms.RandomCrop(32, padding=4),
    transforms.RandomHorizontalFlip(),
    transforms.ToTensor(),
])
eval_transform = transforms.ToTensor()

# 直接对底层样本取两次，观察随机变换。
image, _ = full_train[0]
a = train_transform(image)
b = train_transform(image)
print(torch.equal(a, b))  # 经常是 False

c = eval_transform(image)
d = eval_transform(image)
print(torch.equal(c, d))  # True
```

**思考.** C 要留下。它没有提高最高准确率，但它阻止你把第 40 轮那个更差的权重拿去汇报。汇报用的是验证准确率 0.74 那一份，不是 0.70 那一轮。早停的价值经常是「选对 epoch」，而不只是「把最高分再抬高」。
